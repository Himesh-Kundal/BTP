# Phase 3 (IR, Quantization, Calibration) Walkthrough & Viva Preparation

## 1. What Was Built
In Phase 3, we constructed the mathematical and intermediate representation core of the compiler:
1. **Complete IR Specification (`ir/`)**:
   - `ir/tensor.py`: `TensorRef` and `TensorKind` (`CONSTANT`, `INPUT`, `OUTPUT`) tracking shape, dtype, SHA256 hashes, and lazy sidecar loading.
   - `ir/operators.py` & `ir/linear.py`: `LinearOp` dataclass enforcing Invariants I1 (shape consistency), I2 (quantized weights strictly within $[-127, 127]$, rejecting $-128$), and I3 (`CONSTANT` weight kind for fixed hardware).
   - `ir/graph.py`: Multi-operator graph container with JSON serialization.
   - Serialization (Invariant I4): Lossless saving and loading to JSON with `.npy` sidecar arrays and strict SHA256 checksum verification.
   - Layering compliance (Invariant I5): Strict AST inspection guaranteeing 0 PyTorch or framework imports in `ir/`.
2. **Symmetric INT8 Weight Quantization (`compiler/quantization.py`)**:
   - Implements Rule N2: per-output-channel symmetric scale $s_w[n] = \max |W[n, :]| / 127.0$ in float64.
   - Round-half-to-even `np.rint` tie-breaking.
   - Zero-row corner case produces $s_w = 1.0$ and zero row output.
   - Mathematically proven bound $|W - s_w \cdot W_q| \le s_w/2 + 10^{-12}$ verified across randomized property tests.
3. **Static Activation Calibration (`compiler/calibration.py`)**:
   - Implements Rule N3: per-tensor static scale $s_x = \text{stat} / 127.0$ from calibration activations.
   - Supports absmax and percentile methods (e.g. 99.99%) with graceful zero fallback.
   - Quantizes activations into $[-127, 127]$ (never emitting $-128$).
   - Proven deterministic across repeated runs on real SmolLM2-135M calibration activations.
4. **Synthetic Bias Handling (`compiler/quantization.py`)**:
   - Implements Rule N5: per-channel scale $s_b[n] = s_x \cdot s_w[n]$ to match the INT32 accumulator domain.
   - Clamps safely to 32-bit signed range $[-2^{31}, 2^{31}-1]$.
   - Verified bit-exact against independent integer reference oracle.
5. **Accumulator Bitwidth & Overflow Pass (`compiler/accumulator.py`)**:
   - Implements Rule N4 and N8: computes worst-case bound $K \cdot 128 \cdot 127 + |b_q|_{\max}$.
   - Strictly rejects layers exceeding 32-bit capacity ($\text{bound} \ge 2^{31}$).
   - Computes minimal safe accumulator width $\text{acc\_bits\_min} = \lceil\log_2(\text{bound} + 1)\rceil + 1$ (25 bits for $K=576$, 26 bits for $K=1536$).
6. **Claim C2 Evaluation & Change Control**:
   - Evaluates all 21 layer configurations (7 projection types across layers 0, 14, 29) via `examples/eval_quant_quality.py`.
   - Records empirical results in `results/quant_quality.json`.
   - Freezes acceptance thresholds via `docs/adr/ADR-0001-c2-thresholds.md` (cosine similarity $\ge 0.980$, SQNR $\ge 15.0$ dB, rel-L2 $\le 0.180$), verified by `tests/test_quality.py`.
7. **End-to-End Compiler Driver (`compiler/pipeline.py`)**:
   - Orchestrates calibration, quantization, bias scaling, accumulator bounds, and architecture specialization in a unified pipeline tested on real model weights.

## 2. Answers to P3 Explain-It Questions

### Question 1: Why per-channel weight scales but a per-tensor activation scale?
**Weights are static and known offline**, while **activations are dynamic runtime inputs**.

1. **Accuracy Benefit of Per-Channel Weight Scales**:
   In transformer feed-forward and attention projection layers, different output channels (rows of $W \in \mathbb{R}^{N \times K}$) exhibit widely differing variances and dynamic ranges. If a single per-tensor scale were used, channels with large outlier weights would force a large scale, severely quantizing smaller channels down to zero or a few quantization bins. Per-channel scaling assigns each output channel $n$ its own scale $s_w[n] = \max_k |W[n, k]| / 127.0$, preserving the full dynamic range for every channel.
2. **Zero Hardware Cost**:
   In the matrix-vector dot product:
   $$Y[m, n] = \sum_{k=0}^{K-1} X[m, k] \cdot W[n, k]$$
   The weight scale $s_w[n]$ depends only on the output index $n$ and does not vary across the accumulation index $k$. Therefore, $s_w[n]$ factors cleanly out of the summation:
   $$Y_{\text{float}}[m, n] \approx s_x \cdot s_w[n] \left( \sum_{k=0}^{K-1} X_q[m, k] \cdot W_q[n, k] + b_q[n] \right)$$
   This means the hardware core (both Design F and Design P) operates purely on integer arithmetic. Neither floating-point multipliers nor per-channel scaling circuits exist in the hardware datapath. The per-channel scale is applied entirely in software/post-processing during dequantization. Thus, per-channel weight scaling provides massive accuracy gains at **zero RTL area, zero power, and zero latency cost**.
3. **Hardware Simplicity of Per-Tensor Activation Scale**:
   In contrast, activations $X$ are generated dynamically during inference. A dynamic per-token or per-channel activation scale would require computing a runtime reduction (max-abs over $K$) and dynamic division before each layer, substantially increasing datapath latency and hardware complexity. A static per-tensor scale $s_x$ determined offline during calibration requires no runtime reduction hardware whatsoever.

### Question 2: Why does $K=1536$ never overflow INT32?
The worst-case accumulation analysis demonstrates that overflow is mathematically impossible under our contract:
1. Per Rule N7, input activations are 8-bit signed integers in $[-128, 127]$. The maximum absolute magnitude of any input is $|X_q| \le 128$.
2. Per Rule N2, quantized weights are strictly clipped to $[-127, 127]$ (rejecting $-128$). The maximum absolute magnitude of any weight is $|W_q| \le 127$.
3. The worst-case product of any single multiplication term is:
   $$\max |X_q \cdot W_q| = 128 \times 127 = 16,256$$
4. For the largest linear projection in SmolLM2-135M (`down_proj`, where $K=1536$), the worst-case dot product across all 1536 terms is:
   $$\text{bound} = K \cdot 128 \cdot 127 = 1536 \times 16,256 = 24,969,216$$
5. SmolLM2-135M has zero linear biases ($|b_q|_{\max} = 0$). Even with a synthetic bias, the maximum value of $24,969,216$ represents barely **1.16%** of the positive capacity of a signed 32-bit two's complement integer:
   $$\text{INT32 capacity} = 2^{31} - 1 = 2,147,483,647$$
6. The minimum safe accumulator bitwidth needed to hold this worst-case sum without overflow is:
   $$\text{acc\_bits\_min} = \lceil \log_2(24,969,216 + 1) \rceil + 1 = 25 + 1 = 26\text{ bits}$$
Since $26 \le 32$, a 32-bit accumulator provides 6 full bits of headroom above the absolute worst-case bound, guaranteeing that overflow cannot occur under any circumstances. (Overflow is only reachable when $K \ge 132,105$, which is explicitly rejected by our compiler pass).

### Question 3: What do C1 and C2 each claim?
Our verification methodology enforces a strict separation between hardware correctness and numerical approximation:

1. **Claim C1 (Hardware Bit-Exactness)**:
   $$Y_{\text{RTL}} == Y_{\text{ref\_int64}} \quad \text{(Exact Integer Identity)}$$
   - **What it claims**: The synthesized Verilog circuit executes the integer arithmetic specified by the IR with 100% bit-exact accuracy.
   - **Contract**: Zero mismatches across all test vectors; verified by self-checking testbenches with negative controls and 100% mutation kill rate.
   - **Nature**: Deterministic, non-negotiable verification of digital logic. There are no epsilon tolerances in Claim C1.

2. **Claim C2 (Quantization Numerical Fidelity)**:
   $$Y_{\text{dequant}} \approx Y_{\text{float}} \quad \text{(Statistical Approximation)}$$
   - **What it claims**: The quantized INT8 representation faithfully reproduces the continuous FP32 representation of the original neural network layer when dequantized per Rule N6 ($Y_{\text{dequant}} = s_x \cdot s_w \cdot Y_{\text{int}}$).
   - **Contract**: Evaluated across 4 standard metrics with frozen bounds established in ADR-0001:
     - Cosine Similarity $\ge 0.980$ (measured min: 0.9887, mean: 0.9979)
     - SQNR $\ge 15.0\text{ dB}$ (measured min: 16.36 dB, mean: 26.93 dB)
     - Relative L2 Error $\le 0.180$ (measured max: 0.1520)
     - Maximum absolute error reported.
   - **Nature**: Statistical quality claim characterizing algorithm quantization noise.

By strictly separating C1 from C2, the engineering pipeline guarantees that a hardware design flaw can never be excused as "just quantization error," and quantization inaccuracies can never be confused with RTL arithmetic defects.
