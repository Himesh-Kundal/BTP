## 2. Evidence Summary

- **Design P Baseline Generator (`backend/baseline_p.py`)**:
  - Implements `generate_tile_core_p` for generic $(N_t, K_t)$ tiles with runtime signed multipliers `x_k * w_nk` and explicit 32-bit sign extension.
  - Implements `generate_full_module_p` complete with `W_reg` register array of size $N' \times K'$ INT8 registers, loaded serially via `w_we`, `w_addr`, and `w_data`.
  - Implements `generate_full_module_p_bus`, providing the logic-only baseline variant where weights are supplied via primary-input bus `w_flat` (excluding register array storage area for isolated arithmetic datapath comparisons).
  - Verified in [`tests/test_baseline_p.py`](file:///home/himesh/BTP/tests/test_baseline_p.py).

- **Rule N10 Width Conformance**:
  - Empirically verified that Design P and Design F declare identical input, output, and intermediate signal bit widths:
    - Input activation width: $8 \cdot K'$ bits (`[8*k_padded-1 : 0]`)
    - Multiplier product width: 16 bits signed (`[15:0]`)
    - Accumulator width: 32 bits signed (`[31:0]`)
    - Output bus width: $32 \cdot N'$ bits (`[32*n_padded-1 : 0]`)
  - Verified across symmetric, rectangular, and non-multiple shapes in `test_width_conformance_rule_n10`.

- **Weight-Load Phase Testbench Infrastructure (`backend/vectors.py`, `backend/testbench.py`)**:
  - `write_weight_hex_vectors` dumps $N' \times K'$ weights into `w.hex` in row-major order (2 hex characters per signed byte in two's complement).
  - `generate_wrapper_testbench_p` implements a robust two-phase verification sequence:
    1. *Reset & Weight-Load Phase*: Asserts `rst_n`, then streams $N' \cdot K'$ cycles with `w_we = 1`, sequential addressing `w_addr`, and data `w_data = w_mem[addr]`.
    2. *Inference Streaming Phase*: Deasserts `w_we`, asserts `valid_in` with `x_flat`, and verifies `valid_out` and `y_flat` at latency $L=1$.
  - Synchronization: Checking process synchronizes precisely to `@(negedge w_we)` followed by `@(posedge clk)`, ensuring zero false timing errors.
  - Verified in [`tests/test_testbench_p.py`](file:///home/himesh/BTP/tests/test_testbench_p.py).

- **End-to-End Differential Verification ($Y_F == Y_P == Y_{\text{ref}}$)**:
  - Simulated both Design F and Design P against the independent NumPy INT64 reference oracle across 5 distinct matrix and tile geometries:
    1. **Shape 1 (Toy)**: $1 \times 3$, tile $1 \times 3$ $\implies$ 5/5 vectors PASS, 0 mismatch, 0 timing errors.
    2. **Shape 2 (Square Multiple)**: $8 \times 8$, tile $4 \times 4$ $\implies$ 5/5 vectors PASS, 0 mismatch, 0 timing errors.
    3. **Shape 3 (Rectangular Multiple)**: $16 \times 32$, tile $8 \times 16$ $\implies$ 5/5 vectors PASS, 0 mismatch, 0 timing errors.
    4. **Shape 4 (Non-Multiple with Padding)**: $5 \times 11$, tile $4 \times 4$ (padded to $8 \times 12$) $\implies$ 5/5 vectors PASS, 0 mismatch, 0 timing errors.
    5. **Shape 5 (Real Model Slice)**: SmolLM2 Layer 0 `q_proj` $8 \times 16$ tile $\implies$ 5/5 vectors PASS, 0 mismatch, 0 timing errors.
  - Verified in [`tests/test_differential_f_p.py`](file:///home/himesh/BTP/tests/test_differential_f_p.py).

- **Negative Control Verification**:
  - Injected corrupted weights in `w.hex` in both `tests/test_testbench_p.py` and `tests/test_differential_f_p.py`.
  - In both cases, the testbench immediately caught and reported arithmetic mismatches, confirming that the differential verification harness is highly sensitive to any weight error.

  - Verilator (`verilator --lint-only -Wall`): Clean (0 warnings).
