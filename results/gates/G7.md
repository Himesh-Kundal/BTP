## 4. What the Data Supports vs What It Only Suggests (`docs/06` §B5)

### What the Data Supports:
1. Dense constant-weight specialization in pre-layout logic synthesis yields a **3.0× to 3.85× cell reduction** in the arithmetic datapath compared to generic multipliers.
2. Invariant I3 eliminates runtime weight storage, providing an order-of-magnitude reduction in sequential flip-flops ($>17\times$ at large tile dimensions).
3. Constant folding shortens the combinational critical path proxy (`ltp`) by 20% to 32% across standard gate configurations.
4. Real LLM weights are substantially cheaper to synthesize than uniform random INT8 numbers (~23% smaller) because real weights cluster around zero, yielding low bit-density constant multipliers.
5. Linear tile-sum extrapolation with adder reduction trees matches directly synthesized multi-tile cores with an estimation error $\epsilon < 11\%$.

### What the Data Only Suggests (Caveats):
1. **No Layout Interconnect**: Pre-layout synthesis does not account for wire routing congestion, parasitics, or aspect ratios. While Design F has ~3.5x fewer cells, dense constant routing might affect routing density.
2. **Timing Closure**: `ltp` is a topological gate depth proxy, not static timing analysis (STA) with wire delay under standard cell library PVT corners.
3. **SRAM vs Logic Overhead**: Real programmable accelerators typically store weights in dense SRAM macros rather than flip-flops. However, comparing against `Design P_bus` directly isolates datapath arithmetic area independent of memory choice.
